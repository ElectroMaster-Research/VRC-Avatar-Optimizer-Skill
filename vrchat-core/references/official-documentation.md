# Official VRChat documentation and installed evidence

Use official VRChat documentation for relevant creator, SDK, platform, compatibility, and product-behavior questions.
Open the specific page that supports the claim. Do not rely on search snippets alone.

| Question | Starting source |
| --- | --- |
| Creator workflow and components | [Creator documentation](https://creators.vrchat.com/) |
| SDK setup, APIs, callbacks, and supported Unity versions | [SDK documentation](https://creators.vrchat.com/sdk/) |
| PC, Android, and iOS requirements | [Platform documentation](https://creators.vrchat.com/platforms/) |
| Avatar performance categories and limits | [Performance ranks](https://creators.vrchat.com/avatars/avatar-performance-ranking-system/) |
| VCC, VPM, and official package management | [Creator Companion documentation](https://vcc.docs.vrchat.com/) |

These starting pages were checked on 2026-10-13. They are not frozen specifications.
Follow their current links to the relevant feature and platform pages.
Verify version-sensitive or platform-sensitive claims at task time.
Record the source URL, check date, target platform, and relevant version.
Do not transfer PC limits to Android or infer iOS support from an Android result.
Do not expand the specialist's PC/Android validation coverage without suitable evidence for another platform.

Keep three evidence types separate:

1. Official facts describe documented VRChat requirements or behavior.
2. Installed evidence describes the actual SDK, shader, processor, connector, or editor version.
3. Local workflow evidence describes measured results and proven recovery or validation procedures.

Compare current documentation with installed SDK validators, APIs, rank assets, and actual processed output when the claim depends on them.
Report disagreements with their versions and measurement context.
Do not select the lower metric merely because it passes a target.
Do not replace proven local workflow evidence with generic documentation.
Documentation does not prove a live MCP connection, successful backup, shader parity, or measured build rank.

Use upstream tool documentation and installed source for third-party implementation claims.
ALCOM, Modular Avatar, NDMF, AAO, d4rk, and shaders are not the VRChat SDK.
Label their observed behavior and version separately from official VRChat facts.
Preserve the specialist's authoring-versus-processed Build evidence requirements.

If current documentation is unavailable, identify the inaccessible source and remaining uncertainty.
Use dated local evidence only within its established scope. Do not label it current without verification.
